# lucide-svg-inline

A build-time codegen crate that generates a typed Rust `Icon` enum from [Lucide](https://lucide.dev/) SVG files. Icons are inlined as `&'static str` via `include_str!`, enabling dead code elimination by the Rust compiler — only icons you actually reference end up in your binary.

## Goals

- **Compile-time safety**: Every icon reference is a typed enum variant. Typos don't compile.
- **Minimal binary size**: A manifest file (`lucide-icons.toml`) controls which icons are available. Rust's dead code elimination further strips any listed-but-unused icons when LTO is enabled.
- **Framework-agnostic**: The crate outputs raw SVG strings. No dependency on Dioxus, Leptos, Yew, or any other framework.
- **Fast builds**: Pure string codegen as a `[build-dependencies]` lib — no proc macros, no network calls, no heavy dependencies.
- **LLM-friendly**: Easy for Claude Code to maintain — add/remove icons from a TOML file, regenerate, done.

## Consumer usage

### Cargo.toml

```toml
[build-dependencies]
lucide-svg-inline = "0.1"
```

### lucide-icons.toml

The manifest file listing which Lucide icons to make available. Only these icons will have enum variants generated and SVGs included.

```toml
# Lucide icon names (matching SVG filenames without extension)
icons = [
    "arrow-right",
    "chevron-down",
    "heart",
    "home",
    "menu",
    "search",
    "user",
    "x",
]
```

### build.rs

```rust
fn main() {
    lucide_svg_inline::generate(lucide_svg_inline::Config {
        svg_dir: "vendor/lucide-icons".into(),
        manifest: "lucide-icons.toml".into(),
        svg_defaults: lucide_svg_inline::SvgDefaults {
            // Strip width/height so CSS controls sizing (recommended)
            strip_dimensions: true,
            // Add a class to all icons for global CSS targeting
            default_class: Some("icon lucide".into()),
            // Slightly thinner strokes
            stroke_width: Some(1.75),
            ..Default::default()
        },
    })
    .expect("Failed to generate icon definitions");
}
```

### src/icon.rs

```rust
// This file just pulls in the generated code
include!(concat!(env!("OUT_DIR"), "/icon.rs"));
```

### Application code

```rust
use crate::icon::{Icon, RenderOptions};

// Zero-cost: use the baked-in SVG with build-time defaults
let svg = Icon::Heart.svg();

// Runtime customization: override for a specific use
let big_red_heart = Icon::Heart.render(&RenderOptions {
    size: Some(48),
    stroke: Some("red".into()),
    stroke_width: Some(2.5),
    class: Some("icon icon-hero".into()),
    ..Default::default()
});

// Accessibility attributes via extra_attrs
let close_btn = Icon::X.render(&RenderOptions {
    size: Some(16),
    extra_attrs: vec![
        ("aria-label".into(), "Close".into()),
        ("role".into(), "img".into()),
    ],
    ..Default::default()
});
```

## Generated output

The `generate()` function writes a file to `OUT_DIR` containing:

1. The `Icon` enum with all variants from the manifest
2. A `RenderOptions` struct for runtime customization
3. Methods on `Icon` for both raw access and customized rendering

```rust

/// Source: Lucide v0.575.0
/// Icons: 8 of ~1500 available
#[derive(Debug, Clone, Copy, Hash, Eq, PartialEq)]
pub enum Icon {
    ArrowRight,
    ChevronDown,
    Heart,
    Home,
    Menu,
    Search,
    User,
    X,
}

/// Runtime customization for icon rendering.
/// All fields are optional — `None` means "keep the baked-in default".
#[derive(Debug, Clone, Default)]
pub struct RenderOptions {
    /// Sets `width` and `height` attributes (e.g., `Some(32)` for 32x32).
    /// Only applies if build-time `strip_dimensions` was `false`, or to
    /// re-add dimensions that were stripped.
    pub size: Option<u32>,

    /// Sets `width` and `height` independently (overrides `size`).
    pub width: Option<u32>,
    pub height: Option<u32>,

    /// Override `stroke-width`. Lucide default: `2`.
    pub stroke_width: Option<f32>,

    /// Override `stroke` (color). Lucide default: `"currentColor"`.
    pub stroke: Option<String>,

    /// Override `fill`. Lucide default: `"none"`.
    pub fill: Option<String>,

    /// CSS class(es) to set on the `<svg>` element.
    /// Replaces any class set at build time.
    pub class: Option<String>,

    /// Arbitrary attributes to add/override on the `<svg>` element.
    /// Example: `vec![("aria-label".into(), "Close icon".into())]`
    pub extra_attrs: Vec<(String, String)>,
}

impl Icon {
    /// Returns the raw SVG markup with build-time defaults applied.
    /// This is a static string — zero allocation, zero runtime cost.
    pub fn svg(&self) -> &'static str {
        match self {
            Self::ArrowRight => include_str!("/absolute/path/to/vendor/lucide-icons/arrow-right.svg"),
            Self::ChevronDown => include_str!("/absolute/path/to/vendor/lucide-icons/chevron-down.svg"),
            Self::Heart => include_str!("/absolute/path/to/vendor/lucide-icons/heart.svg"),
            Self::Home => include_str!("/absolute/path/to/vendor/lucide-icons/home.svg"),
            Self::Menu => include_str!("/absolute/path/to/vendor/lucide-icons/menu.svg"),
            Self::Search => include_str!("/absolute/path/to/vendor/lucide-icons/search.svg"),
            Self::User => include_str!("/absolute/path/to/vendor/lucide-icons/user.svg"),
            Self::X => include_str!("/absolute/path/to/vendor/lucide-icons/x.svg"),

    pub fn render(&self, opts: &RenderOptions) -> String {
        let mut svg = self.svg().to_string();

        // This is simple string manipulation — no XML parser needed since Lucide SVGs
        // have a predictable, single-root structure.
        // ...
        svg

    /// Returns the kebab-case name (matching the Lucide icon name).
    pub fn name(&self) -> &'static str {
        match self {
            Self::ArrowRight => "arrow-right",
            Self::ChevronDown => "chevron-down",
            Self::Heart => "heart",
            Self::Home => "home",
            Self::Menu => "menu",
            Self::Search => "search",
            Self::User => "user",
            Self::X => "x",
```

### Note on `include_str!` and build-time transforms

The `svg()` method uses `include_str!` which embeds the file contents at compile time. However, if `SvgDefaults` has any non-default values, the codegen can't use `include_str!` directly — it needs to read the SVG, transform it, and write the modified version to `OUT_DIR` as a new file, then `include_str!` that.

So the actual flow when `SvgDefaults` has customizations:

1. Read `vendor/lucide-icons/heart.svg`
2. Apply transforms (strip dimensions, inject class, change stroke-width, etc.)
3. Write to `OUT_DIR/svgs/heart.svg`
4. Generate `include_str!(concat!(env!("OUT_DIR"), "/svgs/heart.svg"))`

When `SvgDefaults` is all defaults (no transforms needed), the codegen can point `include_str!` directly at the vendor directory for simplicity.

## Public API (lib.rs)

```rust
pub struct Config {
    /// Path to the directory containing Lucide SVG files.
    pub svg_dir: PathBuf,

    /// Path to the TOML manifest listing which icons to include.
    pub manifest: PathBuf,

    /// Build-time SVG defaults. Applied when generating the static SVG strings.
    pub svg_defaults: SvgDefaults,
}

/// Controls how SVG markup is transformed at build time.
/// These are baked into the `include_str!` output — zero runtime cost.
pub struct SvgDefaults {
    /// Remove `width` and `height` attributes from the `<svg>` element,
    /// keeping only `viewBox`. This lets CSS control sizing via classes
    /// or inline styles. Default: `true`.
    pub strip_dimensions: bool,

    /// CSS class(es) to inject on every `<svg>` element.
    /// Example: `Some("lucide-icon".into())`
    /// Default: `None`.
    pub default_class: Option<String>,

    /// Override the `stroke-width` attribute on the `<svg>` element.
    /// Lucide default is `2`. Thinner icons: `1.5`. Bolder: `2.5`.
    /// Default: `None` (keep Lucide's default of `2`).
    pub stroke_width: Option<f32>,

    /// Override the `stroke` (color) attribute on the `<svg>` element.
    /// Lucide default is `"currentColor"` (inherits from CSS `color`).
    /// Default: `None` (keep `currentColor`).
    pub stroke: Option<String>,

    /// Override the `stroke-linecap` attribute.
    /// Lucide default is `"round"`. Options: `"butt"`, `"round"`, `"square"`.
    /// Default: `None` (keep `round`).
    pub stroke_linecap: Option<String>,

    /// Override the `stroke-linejoin` attribute.
    /// Lucide default is `"round"`. Options: `"arcs"`, `"bevel"`, `"miter"`, `"round"`.
    /// Default: `None` (keep `round`).
    pub stroke_linejoin: Option<String>,

    /// Override the `fill` attribute.
    /// Lucide default is `"none"`. Typically leave this alone.
    /// Default: `None` (keep `none`).
    pub fill: Option<String>,
}

impl Default for SvgDefaults {
    fn default() -> Self {
        Self {
            strip_dimensions: true,
            default_class: None,
            stroke_width: None,
            stroke: None,
            stroke_linecap: None,
            stroke_linejoin: None,
            fill: None,
        }
    }
}

/// Generates the Icon enum source file in OUT_DIR.
///
/// Call this from build.rs. Emits appropriate `cargo:rerun-if-changed`
/// directives for both the manifest and the SVG directory.
pub fn generate(config: Config) -> Result<(), Error>;
```

### Lucide SVG anatomy

For reference, a raw Lucide SVG looks like this:

```svg
<svg
  xmlns="http://www.w3.org/2000/svg"
  width="24"
  height="24"
  viewBox="0 0 24 24"
  fill="none"
  stroke="currentColor"
  stroke-width="2"
  stroke-linecap="round"
  stroke-linejoin="round"
>
  <path d="M20.84 4.61a5.5 5.5 0 0 0-7.78 0L12 5.67l-1.06-1.06a5.5 5.5 0 0 0-7.78 7.78l1.06 1.06L12 21.23l7.78-7.78 1.06-1.06a5.5 5.5 0 0 0 0-7.78z"/>
</svg>
```

All customizable attributes are on the root `<svg>` element. The inner `<path>`, `<circle>`, `<line>`, etc. elements inherit from the root and should not be modified.

### Build-time vs runtime customization

**Build-time** (`SvgDefaults`): Modifies the SVG strings at codegen. Zero runtime cost — the final strings are baked into the binary via `include_str!`. Use this for project-wide defaults.

**Runtime** (`RenderOptions`): The generated code includes a `render()` method that applies per-use overrides by string-replacing attributes on the root `<svg>` element. Small runtime cost but fully flexible. See generated output below.

## Implementation details

### Name conversion

Lucide SVG filenames are kebab-case (e.g., `arrow-right.svg`). Convert to PascalCase for enum variants:

- `arrow-right` → `ArrowRight`
- `chevron-down` → `ChevronDown`
- `x` → `X`
- `2fa` → `TwoFa` (leading digits get word-mapped: 0→Zero, 1→One, etc.)

### cargo:rerun-if-changed

The `generate()` function must emit:

```
cargo:rerun-if-changed=lucide-icons.toml
cargo:rerun-if-changed=vendor/lucide-icons
```

So the build step re-runs when the manifest changes or icons are updated, but not on every build.

### include_str! paths

The `include_str!` macro needs absolute paths since the generated file lives in `OUT_DIR`. Use `std::fs::canonicalize()` on the `svg_dir` to get the absolute path at codegen time.

### Error handling

`generate()` should fail the build with clear messages when:

- An icon listed in `lucide-icons.toml` doesn't have a matching `.svg` file in `svg_dir`
- The `svg_dir` doesn't exist
- The manifest file is malformed

Use `panic!` or return an error that the consumer's `build.rs` can `.expect()` on — this produces a clear compile error.

## Vendoring Lucide SVGs (xtask)

The consumer project should include an xtask command to download Lucide icons. This is NOT part of the crate itself — it lives in the consumer's workspace.

### xtask fetch-icons

Downloads a specific Lucide release and extracts only the SVG icon files:

```
cargo xtask fetch-icons 0.575.0
```

This should:

1. Download `https://github.com/lucide-icons/lucide/archive/refs/tags/0.575.0.tar.gz`
2. Extract only files matching `lucide-0.575.0/icons/*.svg` (flat, no subdirectories)
3. Write them to `vendor/lucide-icons/`
4. Write a `vendor/lucide-icons/VERSION` file containing the tag

The vendored SVGs get committed to the repo. Approximately 1500 files at ~500 bytes each ≈ ~750KB total.

## Dependencies (of the crate)

Keep these minimal since it's a build dependency:

- `toml` — parse `lucide-icons.toml`
- `heck` — case conversion (kebab → PascalCase). Optional: this is simple enough to hand-roll if you want zero deps.

That's it. No `serde`, no `syn`, no `quote`. Just string formatting.

The SVG attribute manipulation (both build-time and runtime) is simple string replacement on the opening `<svg ...>` tag — no XML parser crate needed. Lucide SVGs have a predictable single-root structure.

## Testing

- **Unit tests**: Given a temp directory with a few SVG files and a manifest, assert the generated Rust code is valid and contains the expected variants.
- **Integration test**: Include a small test project that actually compiles the generated code and verifies `Icon::Heart.svg()` returns valid SVG content.
- **Error tests**: Missing SVG file, empty manifest, malformed TOML — all should produce clear errors.

## Future considerations

These are NOT in scope for v0.1 but worth keeping in mind:

- **Framework helpers**: Optional feature flags that generate Dioxus/Leptos/Yew components wrapping the raw SVG. Should live in separate crates (e.g., `lucide-svg-inline-dioxus`).
- **Category filtering**: Instead of listing individual icons, allow `categories = ["arrows", "media"]` using Lucide's metadata. Requires parsing their `categories.json`.
- **Auto-scan mode**: Scan `src/**/*.rs` for `Icon::VariantName` patterns and auto-generate the manifest. Adds complexity but removes manual maintenance.
- **RenderOptions in TOML**: Allow per-icon overrides in `lucide-icons.toml` for build-time variants (e.g., always render `x` at stroke-width 3).
